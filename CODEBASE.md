# Codebase Map — Webflow export vs. custom code

> Read this first. This site is a **Webflow static export** that has been
> hand-edited. The hard part is telling apart what Webflow generated from what
> was added by hand. This file documents that boundary precisely so you don't
> have to reverse-engineer it.
>
> **Baseline:** the untouched Webflow export lives in git commit `9b6c881`
> ("decrypt exported code"). Anything different from that commit is a hand edit.
> To see every hand change at any time:
>
> ```bash
> git diff 9b6c881 HEAD -- . ':(exclude)media-web/**' ':(exclude)media/**' ':(exclude)fonts/**'
> ```

---

## 1. Legend

| Tag | Meaning |
| --- | --- |
| **[WF]** | Generated by Webflow. Do **not** hand-edit; it will be overwritten on the next export. Treat as read-only / vendor code. |
| **[WF+]** | Webflow-generated file that contains **hand-added blocks**. Mixed origin — edit only the marked blocks. |
| **[NEW]** | Written by hand from scratch. Safe to own and edit freely. |

## 3. The one rule for staying sane

**Custom CSS belongs in `css/site-layout.css`. Webflow CSS belongs in the
`.webflow.shared.min.css` file and must not be touched.**

Both are linked in every page's `<head>`, with the custom file **after** the
Webflow one so it can override:

```html
<link href="css/anjas-top-notch-site-...webflow.shared....min.css" rel="stylesheet" />  <!-- [WF] -->
<link href="css/site-layout.css" rel="stylesheet" />                                     <!-- [NEW] -->
```

There is currently **one deliberate exception** (an inline `<style>` block in
`about.html`) — documented in §5 so it isn't mistaken for Webflow output.

## 4. What `css/site-layout.css` does (all [NEW])

Three concerns, in order:

1. **Strict project grid** (`.projects.projects-grid …`): forces every project
   card image onto the same baseline using CSS grid + fixed-height image
   wrappers (`height: 200px; object-fit: cover`).
2. **Award badge overlay** (`.has-badge` / `.has-badge-cell` / `.award-badge`):
   absolutely-positioned Z-Kubator sticker. Size is context-dependent and uses
   `!important` **on purpose** — the Webflow grid rule
   `.projects-grid … .image-wrapper img` is more specific and would otherwise
   stretch the badge to fill the card:
   - homepage card: `clamp(70px, 22%, 150px)`
   - projects grid (crop) card: `clamp(40px, 22%, 64px)`
   - Touriski detail image: `clamp(64px, 14%, 150px)`
3. **About page layout** (`.about-*`): timeline rows, bio spacing, contact link
   resets. Only used by `about.html`.

## 5. Boundary cases — custom code living inside Webflow files

These are the only spots where hand code is mixed into Webflow-origin files.
Flagged here so a future editor (human or LLM) doesn't assume the whole file is
one origin.

### a) `js/webflow.schunk.1124e0e3e6df0e88.js` — Figma card dark cursor
A 2-character edit swaps the hover interaction id for the Figma project card so
it triggers the **dark** arrow cursor (`a-10`) like the Localista card, instead
of the white one (`a-20`). Everything else in this file is untouched Webflow
IX2 output. **If the site is re-exported from Webflow, this edit is lost** —
either redo it or set the interaction inside Webflow itself.

### b) `about.html` inline `<style>` block
`about.html` is fully custom, but it carries a small inline `<style>` in
`<head>` (link color resets, `.about-contact-block`/`.about-contact-line`
stacking so email + LinkedIn sit on separate lines, `.event-link` underline).
This is **[NEW]**, not Webflow. It lives inline only because it is tightly
coupled to that one page; it could be moved into `site-layout.css` if desired.

### c) Native cursor reuse on `about.html` links
The About-page links (email, LinkedIn, and the three nomination links) carry
real Webflow `data-w-id` attributes copied from existing project-card link
blocks. This makes Webflow's own IX2 engine animate the native dark arrow
cursor on hover — **no custom cursor JS**. (An earlier custom-JS approach was
removed; its leftovers are the retired `archive/contact.*` files.)

### d) SEO blocks in every [WF+] HTML file
Each Webflow HTML page has a hand-added block near the end of `<head>`:
`<link rel="canonical">`, `<meta name="description">`, Open Graph / Twitter
tags. Webflow's own duplicate `og:`/`twitter:` metas were removed to avoid
conflicts. These blocks are **[NEW]** even though the surrounding file is [WF].

## 6. If you re-export from Webflow (what you lose)

A fresh Webflow export overwrites `index.html`, `projects.html`,
`projects/*.html`, the `.webflow.*.min.css`, and the `js/webflow.*` bundles.
That wipes, and you must re-apply:

- the IX2 edit in §5a,
- all SEO blocks (§5d) and `alt` text,
- the award-badge markup on Touriski cards,
- the Touriski collaboration links.

`about.html`, `css/site-layout.css`, `_headers`, `robots.txt`, `sitemap.xml`,
and `media-web/z-kubator.*` are **not** produced by Webflow and survive an
export untouched.
